# คู่มือการนำเสนอโครงการ: Student Risk & Performance Segmentation (Supervised Learning)

## 1. บทสรุปสำหรับผู้บริหาร (Executive Summary)

โครงการนี้สร้างระบบการเรียนรู้แบบมีผู้สอน (Supervised Machine Learning System) เพื่อทำนายสถานะความสำเร็จของนักศึกษา (Course Completion / Certification) และจัดกลุ่มระดับความเสี่ยง (Student Risk Tiers) ออกเป็น 3 กลุ่มเชิงปฏิบัติการ ได้แก่:
1. **Tier 1 (ความเสี่ยงต่ำ / มีแนวโน้มสำเร็จสูง, $p \ge 50\%$):** นักศึกษาที่มีความพร้อมสูง ส่งเสริมด้วยเนื้อหาขั้นสูงและบทบาทพี่เลี้ยง (Peer Mentors)
2. **Tier 2 (ความเสี่ยงปานกลาง / กลุ่มเป้าหมายที่ต้องการการสะกิดเตือน, $15\% \le p < 50\%$):** มีความร่วมมือในการเรียนแต่เริ่มชะลอตัว ระบบจะส่งการแจ้งเตือน (Nudges) แนะนำกลุ่มอ่านหนังสือ และตารางงาน
3. **Tier 3 (ความเสี่ยงสูง / เสี่ยงออกกลางคันเร็ว, $p < 15\%$):** เข้าเรียนน้อยมาก ต้องการการติดต่อช่วยเหลือโดยตรง (Advisor Outreach) การปูพื้นฐาน และการซ่อมเสริม

## 2. ประเด็นสำคัญด้านการออกแบบระบบและวิศวกรรมข้อมูล (Key Technical Architecture)

### 2.1 การป้องกันข้อมูลรั่วไหลอย่างเคร่งครัด (Strict Anti-Leakage Governance)
- ในงานวิจัยทางการศึกษา ข้อผิดพลาดที่พบบ่อยที่สุดคือการนำตัวแปรผลลัพธ์ปลายทาง (เช่น `grade`, `incomplete_flag`, `explored`, `certified`) เข้าไปเป็น Feature ร่วมในการเทรนโมเดล
- ในโครงการนี้ ได้ทำการแยกตัวแปรเป้าหมายทั้งหมดออกจากข้อมูล Feature ทันทีในขั้นตอนที่ 2 และจัดเก็บไว้ใน `data/labels/` อย่างเป็นเอกเทศ
- ในขั้นตอน Feature Engineering มีการแบ่งข้อมูล Train (70%), Validation (15%), Test (15%) **ก่อน**ที่จะทำการคำนวณและฟิต Pipeline แปลงข้อมูล เพื่อไม่ให้เกิด Data Snooping หรือ Information Leakage

### 2.2 การจัดการปัญหาข้อมูลไม่สมดุล (Severe Class Imbalance)
- ข้อมูลจริงในระบบ MOOC มีผู้เรียนสำเร็จเพียงประมาณ 4.13% (13,881 คน จาก 335,650 คน)
- การวัดผลจึงไม่ใช้ Accuracy ทั่วไป แต่ใช้ **PR-AUC (Precision-Recall AUC)**, **ROC-AUC**, **Balanced Accuracy** และ **Brier Score**
- มีการปรับจูน Decision Threshold ($\tau^*$) เพื่อให้โมเดลสามารถดักจับกลุ่มเสี่ยงได้อย่างมีประสิทธิภาพสูงสุดโดยไม่เกิด False Alert มากเกินไป

## 3. ผลการทดลองและการเปรียบเทียบโมเดล (Empirical Benchmark Results)

ทดสอบจริง 14 การตั้งค่าจาก 10 ตระกูล โดยแยก “ตระกูลโมเดล” ออกจาก “การเปลี่ยนค่าพารามิเตอร์” ได้แก่:
1. **Dummy Baseline:** ค่าฐานอ้างอิง (PR-AUC 0.0414)
2. **Logistic Regression:** โมเดลเชิงเส้นที่ตีความง่าย
3. **SGD ElasticNet:** โมเดลเชิงเส้นแบบ Sparse และรองรับข้อมูลขนาดใหญ่
4. **Gaussian Naive Bayes:** โมเดลความน่าจะเป็นที่ฝึกเร็ว
5. **Calibrated Linear SVM:** เส้นแบ่งแบบ Maximum Margin ที่ปรับให้คืนค่าความน่าจะเป็นได้
6. **Decision Tree:** กฎการตัดสินใจแบบไม่เชิงเส้นที่อธิบายได้
7. **Random Forest:** รวมต้นไม้จากตัวอย่าง bootstrap เพื่อลดความแปรปรวน
8. **Extra Trees:** รวมต้นไม้ที่สุ่มจุดแบ่งมากกว่า Random Forest
9. **HistGradientBoosting:** เรียนรู้ต้นไม้ต่อเนื่องเพื่อแก้ข้อผิดพลาดของรอบก่อน
10. **MLP:** โครงข่ายประสาทเทียมสำหรับความสัมพันธ์ไม่เชิงเส้น

ผู้ชนะคือ **Random Forest (Depth=15, 100 Trees)** เพราะได้ Validation PR-AUC สูงสุด 0.8529 ก่อนเปิดดูชุดทดสอบ ไม่ได้เลือกจาก Accuracy หรือจากผลบน Test set

### ผลการประเมินบนชุดทดสอบจริง (Holdout Test Set):
- **ROC-AUC:** 0.9933 สูงกว่าเกณฑ์ 0.85
- **PR-AUC:** 0.8476 หรือประมาณ 20.5 เท่าของค่าฐาน 0.0414
- **Recall:** 0.8420 ที่ threshold 0.8404 หมายถึงตรวจพบผู้สำเร็จจริงประมาณ 84.2%
- **Brier Score:** 0.0216 ใช้ตรวจคุณภาพค่าความน่าจะเป็น โดยค่ายิ่งต่ำยิ่งดี

## 5. แนวทางการนำเสนอต่อผู้บริหารและคณะกรรมการ

1. **สไลด์ที่ 1-2 (บทนำและปัญหา):** อัตราการ Drop out ของ MOOC สูงถึง 96% ทำให้การดูแลนักศึกษาแบบเดิมไม่สามารถทำได้ทั่วถึง จึงต้องใช้ AI ในการระบุ Risk Tier ล่วงหน้า
2. **สไลด์ที่ 3-4 (การกำกับดูแลและความปลอดภัย):** อธิบายการแยก Target ออกจาก Features (Anti-Leakage) และจริยธรรม AI โดยเน้นย้ำว่าโมเดลมีไว้เพื่อ "ช่วยเหลือ" ไม่ใช่เพื่อ "ลงโทษหรือคัดออก"
3. **สไลด์ที่ 5-6 (ผลลัพธ์ทางเทคนิค):** แสดง 10 ตระกูล/14 การตั้งค่า อธิบายว่าเลือก Random Forest จาก validation PR-AUC แล้วจึงรายงานผล holdout test
4. **สไลด์ที่ 7-8 (การนำไปใช้จริง):** สาธิต Interactive Student Simulator ในไฟล์รายงาน `reports/student_risk_prediction_report.html` ที่ให้ผู้สอนปรับตัวแปรแล้วเห็นความเสี่ยงและมาตรการช่วยเหลือแบบเรียลไทม์
